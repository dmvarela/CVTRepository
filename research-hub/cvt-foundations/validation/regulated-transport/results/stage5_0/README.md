# Stage 5.0 Relational-Routing Protocol

Stage 5.0 freezes the next development cycle without executing it. The protocol converts the Stage 4 counterexample hypotheses into a prospective, capacity-controlled test using only fresh evidence.

Frozen design:

- 24,000 fresh development rows divided into fit, tune, calibration, and selection partitions;
- an 8,000-row fresh validation partition generated only after the winning candidate and validation plan are locked;
- four pre-outcome feature groups totaling 31 encoded columns: local state, scheduled input, declared history, and eight frozen sham-adjusted probe level/slope/contrast summaries;
- 12 prespecified interactions motivated by the two load-bearing contradiction classes;
- additive and interaction-based relational candidates, capacity-matched native logistic and gradient-boosting baselines, and the full native gradient booster as a separate performance ceiling;
- separate hosting, target, damage, integrity, productive-uptake, rejection, buffering, and recovery endpoints;
- frozen Brier, uncertainty, calibration, compression, forcing-family, integrity, and event-count rules.

The Stage 3 row-level evidence is forbidden for Stage 5 fitting, tuning, calibration, selection, and validation. `repeated_pulse` remains reserved. Post-outcome routing variables cannot be used as predictors.
